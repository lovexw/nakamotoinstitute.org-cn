正如[有人指出的](https://twitter.com/jgarzik/status/736945669978525696)，我在写[之前的文章](/mempool/the-coming-demise-of-altcoins)涉及到以太坊时，对它的理解并不深入。我将以太坊当作另一个多了些花哨功能的山寨币。然而，那里隐藏着一个巨大的机会，任何足够了解这个系统的人都可以利用。我真希望我更深入地研究了它，因为现在有一个做到了这一点的人——[一个我现在非常敬佩的人](http://pastebin.com/CcGUBgDG)——手里握着三百万个以太币。
_更新：_ 这个留言[可能不是](https://news.ycombinator.com/item?id=11927891)真正的黑客发的。我仍然同意其论点。

这个人发明了智能合约时代的全新投资策略：你只需找到一个利用智能合约的方法，使其将资金转入你的账户，然后投入资金以控制它，从而[提取资金](http://hackingdistributed.com/2016/06/18/analysis-of-the-dao-exploit/)。

以太坊确实与其他山寨币不同。如果我更仔细地审视以太坊，我可能注意到以太坊开发者不理解的学科不仅仅是经济学。他们也不理解法律和软件工程。他们创造了一个在法律上可利用漏洞的环境中预期会出现漏洞的局面。那是黑客的天堂。

假设 A 想要给 B 发送以太币。我将 `A→B` 写成一个原子操作，它从 `A` 的余额中扣除资金并加到 `B` 的余额上。如果 `A` 的余额不够，这个操作就失败。在以太坊中发送资金，就像我们有这样一个函数：

<pre>
send[f, x, y] = If[
	// 向 B 发送资金并调用 f；如果产生错误则回滚。
	Try[ A→B; f[]; True, False],
	// 如果没有产生错误则调用这个。
	x[],
	// 如果产生了错误则调用这个。
	y[] ]
</pre>

其中 `x` 和 `y` 是 `A` 提供的函数，`f` 是 `B` 提供的函数。换句话说，`A` 把以太币发给 `B`，`B` 立刻可以调用一个函数，对自己的钱做任何想做的事。那个函数就是 `f`。如果他的函数出于某种原因失败了，`A→B` 就被回滚，函数 `y` 被执行。否则，`x` 被执行。任何人都可以提供*任何*函数在接收资金时执行。[^1]

这已经够噩梦了，但假设你有一个对黑客开放的公共函数，形式如下：

<pre>
hackMe[f] =
    // 用 q 检查我们是否欠攻击者的钱。
    If[q[], send[f, x, y]]
</pre>

其中 `q` 是一个函数，如果攻击者无权索取资金，它就应该失败。

假设黑客调用了 `hackMe`，并提供了一个如下形式的 `f`：

<pre>
f[] = p[]; hackMe[f]
</pre>

如果黑客能让 `q` 不恰当地成功，那么调用 `hackMe` 时将执行以下代码：

<pre>
q[]; A→B; p[]; q[]; A→B; p[]; ... q[]; A→B; y[] ...
</pre>

如果没有其他东西阻止这个执行，它最终会在 `A→B` 因 A 资金不足而失败时停止。如果调用栈满了或者计算耗尽了 [gas](https://www.cryptocompare.com/coins/guides/what-is-the-gas-in-ethereum/)，它也可能失败，但这些都是在根本问题之上的复杂性。黑客可以尝试确保只有最后一次发送失败，从而拿走一切。

解决这个漏洞的一种天真的方法是编写 `q`，让它跟踪欠 `B` 多少钱，如果钱已经应该支付了就失败。然而，这种方法不够好，因为与此同时，从函数 `p` 中，攻击者可能运行更多你提供给他并可访问的代码，从而创造进一步的负债。以太坊团队发布的将 DAO 1.0 升级到 1.1 的修复就采用了这种天真的方法，详见[这里](http://hackingdistributed.com/2016/06/18/analysis-of-the-dao-exploit/#was-1-1-vulnerable)。

我提供了一个结果为提取资金的场景，但这个问题比这更普遍。你可以把以太坊智能合约想象成面向对象编程中的一个对象，它有一组任何其他合约都可以调用的公共方法。如果你调用另一个合约的公共方法，它可以调用*你的*任何公共方法，并试图搞乱你的内部状态。根据恶意合约的不同行为有不同的名称（比如[重入和太阳风暴](https://blog.blockstack.org/solar-storm-a-serious-security-exploit-with-ethereum-not-just-the-dao-a03d797d98fa#.wpg35euyp)），但问题实际上是同一种问题——就像你让别人在你自己的电脑上运行他们想要的任何代码一样。

这个问题如此严重，以至于不能被视为 DAO 的一个漏洞。问题在于 <s>Solidity 本身，也就是以太坊中使用的脚本语言。</s> _更新：_ 问题实际上一直深入到以太坊虚拟机。在阅读 Solidity 文档时，我注意到了这一点：

> 如果 `x` 是一个合约地址，它的代码（更具体地说：它的回退函数，如果存在的话）将随着 `send` 调用一起执行（这是 EVM 的一个限制，无法避免）。

这意味着同样的问题存在于 [Serpent](https://mc2-umd.github.io/ethereumlab/docs/serpent_tutorial.pdf)（另一种以太坊脚本语言）以及他们可能提出的任何其他语言中。

想象一个充满热情的新程序员在写他的第一个大型合约："让我看看……"他想。"我使用了 send 函数。这意味着我必须搜索我写的哪些代码块可能被攻击者在无限循环中运行，直到没有钱为止。首先，哪些可能的代码块可以被放入无限循环？可能是任何调用 send 的部分，夹杂着攻击者想要在中间调用的任何东西……嗯……"你每次给任何人发钱的时候都必须这样思考。期望任何人可靠地做到这一点是完全荒谬的。唯一的区别是新手每次尝试写合约都会失败，而专家甚至都不会去尝试。

现在我已经描述了这个问题，使得正在发生的事情非常清楚，但在 Solidity 中，我称为 `f` 的函数对程序员来说不太可见。它是一个叫做"默认函数"的方法，可以在每个地址上定义。当你向那个地址发送资金时它会自动执行。所以如果我 用 Solidity 写 `hackMe`，我不会像我所写的那样直接引用函数 `f`，但它仍然会执行。在 Solidity 中很容易写出 `hackMe`。

[Solidity 手册](http://solidity.readthedocs.io/en/latest/)开头写道："Solidity 是一种高级语言，其语法类似于 JavaScript"，仿佛这是值得夸耀的事情。但显然 Solidity 与 JavaScript 的相似之处不仅仅是表面的。Solidity 就像用 JavaScript 编程，只不过你的银行账户可以通过文档对象模型（DOM）来访问。

没有人准备好用 Solidity 写智能合约的一个标志是：以太坊开发团队——设计 Solidity 和 DAO 的人——甚至无法修复自己的漏洞。他们没有能力正确地处理这些漏洞，而且在我看来，其他人也做不到。可靠地编写正确运行的智能合约也许是*可能的*，但目前没有人知道如何做到。开发团队不太可能在短期内解决这个问题，因为他们仍然认为这只是 DAO 的一个漏洞，而不是他们整个系统的严重问题。如果你想要一个你真正可以使用的智能合约，你必须在部署之前*确信*它是没有漏洞的。目前没有 Solidity 开发者可用的已知工具或方法可以提供适当程度的确定性。这样的工具需要数年时间来开发，在它们被广泛使用之前，不应信任任何以太坊智能合约。以太坊注定失败。

这次攻击的法律意义比攻击本身更有趣。因为 DAO 的代码是一个具有法律约束力的合约，你如何论证以说服法官程序的某个行为真的是一个漏洞？DAO 除了它自己的代码之外，没有提供任何东西来说明它应该如何运作。例如，没有[形式化语言的规范](https://www.reddit.com/r/ethereum/comments/4opjov/the_bug_which_the_dao_hacker_exploited_was_not/)，也没有关于其正确性的证明。如果以太坊团队知道如何测试软件，他们可能会产出类似的东西，这也可能提供辅助证据证明任何漏洞都是非故意的。

我完全支持攻击者的行为，我真希望是我先想到的。他的以太币在他能将其兑换为比特币之前可能变得一文不值，但他也可能在执行攻击之前[对以太币进行了大规模做空](http://hackingdistributed.com/2016/06/18/analysis-of-the-dao-exploit/#step-3-the-big-short)，并以这种方式赚取了约 100 万美元。

关于以太坊团队回应的最后评论，我引用 [Emin Gün Sirer](http://hackingdistributed.com/2016/06/17/thoughts-on-the-dao-hack/#what-s-a-hack-when-you-don-t-have-a-spec) 的一段精辟之言：

> 如果攻击者因失误而亏损了，我相信开发者们会毫不犹豫地没收他的资金，并说"这就是程序化货币流动的全新世界中所发生的事情。"当他反而从 DAO 中掏空了硬币时，唯一一致的回应就是称之为做得好。

    > 事情是这样的。在比特币中，地址是与钱包持有的私钥对应的公钥。为了便于理解我撒了一点小谎。但从根本上说，它只是一些数据。在以太坊中，地址可能是类似的——不是合约，而是公钥。但它也可能是另一个智能合约的地址。例如，Mist 客户端鼓励用户在加载后首先创建一个钱包合约。然后用户将该合约的地址作为他们的"钱包地址"提供。其他合约通常不使用任何机制来区分私钥地址和钱包地址。在以太坊中向合约发送资金是一个基本操作，开发者似乎期望它能像在比特币或其他数字货币中一样"正常运行"，也许附带一个交易费。
