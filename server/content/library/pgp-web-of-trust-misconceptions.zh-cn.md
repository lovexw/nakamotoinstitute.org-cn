用来描述 PGP 的一个核心概念是"信任网络"。这让人联想到一个由相互认识并通信的人之间的连接组成的网络。两个想要通信的人，如果存在一条由签名密钥构成的连接路径将他们联系起来，就可以安全地通信。

但这并不完全正确。关于 PGP 密钥签名的一个常常被误解的基本事实是：

你只能与你认识的人（无论是亲自认识还是通过声誉了解）所签名的密钥持有者安全通信。

换句话说，如果我想与 joe@abc.com 通信，只有当他密钥的签名者中有我认识的人时，我才能做到。如果不是这样，我就无法判断他密钥的有效性。

这与对"信任网络"的简单理解相悖。我可能签名了 A 的密钥，A 签名了 B 的，B 签名了 C 的，C 签名了 D 的，D 签名了 Joe 的，但除非我认识 D，否则这一切都没有价值。只有那样我才能信任 Joe 的密钥。

这意味着，在"网络"图景中，我只能与在连接网络中最多相隔两跳的人安全通信。我可以与我认识的人通信，我可以与我认识的人所认识的人通信，仅此而已。

这很不幸，因为简单的网络模型与一些著名的研究相呼应——这些研究表明，随机选取的任何两个人在谁认识谁的连接网络中仅相隔约六步。（这个结果正是电影《六度分隔》标题的由来。）如果你有一个真正支持通过网络模型进行通信的系统，它确实有希望让两个之间没有很长链条的人进行通信。但 PGP 的最大链条长度为二，不允许这样做。

要在一个类似 PGP 的程序中使用真正的信任网络模型，需要添加什么？基本上需要某种方法来判断你不认识的人所做签名的可信度。这最合理的来源是被签名密钥的人。例如，如果有另一种类型的密钥签名，它不仅担保该人的身份，还担保其在签名密钥方面的可信度和谨慎程度，那么这样一串签名链就可以作为真正信任网络的基础。显然，这种签名不能像我们现在这种那样轻易地给出——我们现在往往只需看一眼某个陌生人的驾照就够了——但它们可以给予密友和你认识并信任的人。

更精密的系统可能包括可信度的数值评级，帮助估计任何给定路径的强度。要点是，需要某种此类信息才能允许与网络中距离较远的人通信。

没有这些，我认为我们将继续面临 PGP 无法验证我们想要通信的人的密钥的问题。人们会收集大量的签名清单，希望想和他们通信的人恰好认识其中某个人。中心化密钥验证机构将会出现（比如正在筹建中的 SLED 服务，它将基于一张附有你名字的签名支票来签名密钥）。结果可能是在使用未签名密钥和使用由某个面目模糊的官僚机构签名的密钥之间做选择，这并不比最初的 PEM 构想更好。

（人们可能对本文感到困惑，因为他们以为 PGP 已经是这样工作的了。PGP 确实有一个追随网络的模型，但这仅用于追踪签名。在上面的例子中，我想和 Joe 通信，通过 A、B、C 和 D 有一条到他的链，我们首先必须假设我认识并信任 A、B、C 和 D 全部。在此前提下，PGP 能做的是确定我是否拥有所有这些人的有效密钥。它会注意到 A 签名了 B 的密钥，所以那是有效的。我认识 B 并告诉 PGP 他是可信的，他签名了 C 的密钥，因此那个也是有效的。同样，我认识 C 也认识 D，所以 PGP 可以通过他们追踪这条链。最后来到 Joe，我不认识他，但因为我认识 D 并且 PGP 追踪网络确定 D 的密钥是有效的，PGP 可以确定 Joe 的密钥是有效的。但同样，那只是因为我认识 D 和链中的所有其他人。底线仍然是我只能与我认识的人所认识的人通信。）
