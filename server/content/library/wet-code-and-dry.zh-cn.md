"湿代码"（由大脑解释）和"干代码"（由计算机解释）之间存在着强烈的区别。人类可读的媒体是湿代码，而计算机代码和计算机可读文件（就计算机对其进行有意义处理而言）是"干代码"。法律是湿代码，由受法律约束的人来解释，由执法者来解释（通常有些不同），但最权威地（而且更加不同地）由法官来解释。人类语言主要是湿代码，但就计算机程序粗糙地将一种语言翻译成另一种语言、关键词广告程序解析文本以推测用户最可能点击哪些广告等方面而言，人类语言文本也可以是干代码。传统合约是湿代码，而[智能合约](/library/formalizing-sercuring-relationships/)主要是干代码。[安全财产权](/library/secure-property-titles/)和[域名系统](http://en.wikipedia.org/wiki/DNS)主要是干代码。

即使是"主要是干代码"的东西也常常有令人惊讶的湿润部分。例如，智能合约可以使用对话框向用户传达其性质，并允许用户至少输入一些参数、进行菜单选择等。这些是[认知通道](http://www.truststc.org/pubs/132/Annarita_Giani_Berkeley.ppt)，在湿代码和干代码之间进行转换。同样，域名系统中人类可读的名称是湿代码，适用于域名的商标法也是湿代码。[网络钓鱼](http://en.wikipedia.org/wiki/Phishing)是利用模糊湿代码对认知通道的攻击，这可能就是为什么干代码程序员很难应对它的原因。

湿代码和干代码的语法性质通常非常相似——例如，人类语言和计算机语言通常都可以被[下推自动机](http://en.wikipedia.org/wiki/Pushdown_automata)解析为[上下文无关文法](http://en.wikipedia.org/wiki/Context-free_grammar)。但它们的语义内容通常截然不同，而且湿代码的语义内容对计算机来说通常是无法理解的，原因多种多样且常常神秘。如果我们有足够好的人类语义理论，我们就可以将这些理论编程到计算机中，计算机就会像大脑一样理解了。但在大多数领域我们做不到，所以我们大多无法编程让计算机模拟人类。我相信这些神秘之处主要是因为大脑高度进化的本质与计算机近期且因此天真的设计之间的对比，尤其是计算机缺乏良好的传感器（它们大多仍然比 [Helen Keller](http://en.wikipedia.org/wiki/Helen_Keller) 更加感觉剥夺，而 Helen Keller 有着非常有触觉的触觉）以及相对无法从自然和社会环境中学习。它们聚合不同类型信息的能力，例如通过[概念隐喻](http://en.wikipedia.org/wiki/Conceptual_metaphor)，也相对不发达。

随着计算机变得越来越"聪明"，干代码正在（非常缓慢地）开始承担更多以前只能由湿代码完成的工作。一旦成功模拟了湿代码，它很快就会在许多方面超越湿代码；例如，到目前为止，干代码进行简单算术的速度比普通人类快数十亿倍。正如智能合约的理念所表明的，从湿代码到干代码可以进行许多富有成效的类比，但我们必须记住截然不同的语义、各自的优缺点，以及它们相互交互以解决实际问题的需要。

我不认为存在一种人工智能的"银弹"理论，能够揭开语义之谜并一举赋予计算机智能。我不认为计算机会在某一天通过某种从[哲学僵尸](http://en.wikipedia.org/wiki/Philosophical_zombie)到[感质](http://en.wikipedia.org/wiki/Qualia)的神奇转变而神秘地"醒来"。（在这方面我基本同意 [Daniel Dennett](http://en.wikipedia.org/wiki/Daniel_Dennett) 的观点。）相反，我们将继续一点一点地形式化人类智能，永远不会到达一个"奇点"——在某一天突然醒来发现计算机已经超越了我们。相反，对于我们学会教计算机做的每一项特定窄能力，都会有多次"微失控"——例如过去一个世纪左右计算机在基本算术方面对人类的优越性。计算机和人类将继续共同进化，计算机进步更快但远未达到关于"[奇点](http://en.wikipedia.org/wiki/Technological_singularity)"的末日预言，除非文明本身已经是一个滚动奇点。例如，人们通常无法预测市场中接下来会发生什么，或者哪些初创公司最终会成功。
