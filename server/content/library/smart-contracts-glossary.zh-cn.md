<a name="agent"></a>_代理（Agent）_：一个人或组织，通常由真名或化名代表。也指由代理控制并代表代理行事的计算机程序。更一般地，化名与持久行为模式的组合，可以据此建立声誉。注意这与"代理"的法律和商业定义不同，但更接近经济学和计算机科学中对该术语的使用。

<a name="contract"></a>_合约（Contract）_：代理之间的一组协议或承诺。

<a name="parties"></a>_当事方（Parties，又称委托人 Principals）_：已同意该合约的代理。

<a name="thirdparties"></a>_第三方（Third Parties）_：未同意该合约的代理。

<a name="performance"></a>_履行（Performance）_：执行合约中规定的承诺。

<a name="contractualsecurity"></a>_合约安全（Contractual Security）_：在组织之间做出安全安排的范式，基于两个主张：(1) 组织间安全的首要目标是保护和执行合约的履行，(2) 在实现这一目标的地方，对该组织合约的安全履行而言，对声誉、外部强制执行和其他因素的依赖被最小化。

<a name="contractualkeydistribution"></a>_合约密钥分发（Contractual Key Distribution）_：在个人和组织之间分发密钥的范式，其中密钥分发和证书结构反映了当事方之间的合约安排。

<a name="protocol"></a>_协议（Protocol）_：多个代理之间的消息序列。

<a name="smartcontract"></a>_智能合约（Smart contract）_：一组承诺，包括当事方在其中履行其他承诺的协议。这些协议通常通过计算机网络上的程序或其他形式的数字电子设备来实现，因此这些合约比其纸质前身"更智能"。不意味着使用人工智能。

<a name="aliceandbob"></a>_Alice 和 Bob_：智能合约的范例当事方。

<a name="eve"></a>_Eve_：范例窃听者，其目标是获取关于合约及其履行的有价值信息，而不是作为合约的当事方。

<a name="mallet"></a>_Mallet_：范例主动攻击者。他的目标可能是窃取智能合约履行中涉及的某些有价值的东西，或者使合约当事方无法获得它。他可能是经济理性的代理，追求纯粹的个人利益，或者是拜占庭式的——最坏情况下的攻击者，不惜个人损失对一方或多方造成最大可能的损害。

<a name="mediator"></a>_调解人（Mediator）_：实时参与智能合约当事方之间协议的第三方，被信任了解该合约的部分内容和/或履行。

<a name="arbitrator"></a>_仲裁人（Arbitrator）_：被信任了解合约的部分内容、部分履行历史，并被合约当事方信任以公正解决由该合约引起的争议的第三方。

<a name="unbundling"></a>_解绑（Unbundling）_：信任分发的原则。解绑调解和仲裁功能可以分离任务、分散风险、最小化脆弱性并减少可链接性，但通常以更大的复杂性为代价。

<a name="enemy"></a>_敌人（Enemy，又称攻击者 attacker）_：其偏好可能导致另一个代理受到损害的代理；影响合约履行以损害一方或双方利益的第三方。

<a name="object"></a>_对象（Object）_：此处泛指任何类型的数字数据，可以是密钥、凭证、合约、程序或各种其他东西。

<a name="credential"></a>_凭证（Credential）_：一个代理关于另一个代理的声明。

<a name="positivecredential"></a>_正面凭证（Positive credential）_：关于一个代理的声明，该代理倾向于揭示，例如名校学位。

<a name="negativecredential"></a>_负面凭证（Negative credential）_：关于一个代理的声明，该代理倾向于不揭示，例如不良信用评级。

<a name="cryptographicprotocol"></a>_密码学协议（Cryptographic protocol）_：使用数学原理和密钥来实现智能合约目标的协议。

<a name="privity"></a>_私密性（Privity）_：只有合约当事方（包括其指定的仲裁人）才需要了解或控制该合约的内容和履行的原则。作为智能合约目标的私密性是法律上私密性原则的推广。它将"不关你的事"这一传统形式化。对私密性的攻击以窃听者 Eve（内容和履行的被动观察者）和恶意破坏者 Mallet（主动干扰履行或窃取价值）为代表。因此，隐私和保密性——即保护有关合约及其当事方和履行的信息价值免受 Eve 侵害——被归入私密性之下。私密性经常与可观察性和可验证性发生冲突。

<a name="observability"></a>_可观察性（Observability）_：合约当事方观察彼此履行该合约的能力，或向对方证明其履行的能力。也指区分故意违反合约和善意错误的能力。智能合约设计的一个重要目标，经常与私密性发生冲突。

<a name="verifiability"></a>_可验证性（Verifiability）_：一方向仲裁人证明合约已被履行或违约的能力，以及区分故意违反和善意错误的能力。智能合约设计的一个重要目标，经常与私密性发生冲突。

<a name="reputablename"></a>_声誉名称（Reputable name）_：具有良好声誉的化名或真名，通常因为它携带许多正面凭证、拥有良好的信用评级，或受到其他方面的高度评价。公司力求拥有知名品牌名称，而医生和律师等专业人员力求获得许多良好的个人推荐。声誉名称很难在代理之间转让，因为声誉假设行为的持续性，但有时这种转让会发生（例如公司之间的品牌名称出售）。

<a name="truename"></a>_真名（True name）_：将许多不同类型的信息联系到一个代理身上的标识符，例如完整的出生姓名或社会安全号码。如同在魔法中一样，知道真名可以赋予敌人巨大的力量。它也可以在和平合作者中具有重大经济价值，例如在直接营销中使用产品信息定向最可能对特定产品感兴趣的代理。

<a name="mix"></a>_混合（Mix）_：一种用于消息传递的密码学协议，其中 Eve 对谁在与谁通信的分析（流量分析）通过发送方用链中每个混合操作者的公钥对消息进行俄罗斯套娃式加密以及每个操作者对消息的混合来防止，使得全景式窃听者 Eve 失去对消息的追踪。只需 N 个操作者中的1个被信任处理流量信息，尽管 Eve 有时可以通过大量消息的统计分析最终猜测谁在与谁通信。通信双方也可以相互匿名，且通过正常的加密，无需信任其他方处理消息内容。保密消息传递是 Chaum 式凭证和不记名证券的一些私密性特征在实际网络上强健实现的必要条件。另一种保密消息传递系统是"密码学家晚餐"网络，同样由 Chaum 发明。

<a name="nym"></a>_化名（Nym）_：仅将少量相关信息联系到一个人的标识符，通常是化名持有者认为与特定组织或社区相关的信息。化名的例子包括电子公告板昵称、笔名、别名和品牌名称。化名可以在其社区内获得声誉。例如，一家企业集团可能销售各种品牌名称，每个品牌在其自己的市场细分中都有声誉。使用 Chaum 式凭证，化名可以利用持有者其他化名的正面凭证，通过"是人凭证"可证明地链接。

<a name="namespace"></a>_名称空间（Name space）_：一组具有简单语法的短标识符，例如电话号码、计算机可读的互联网地址编号、人类可读的互联网域名等。

<a name="chaumiancredentials"></a>_Chaum 式凭证（Chaumian credentials）_：一种密码学协议，用于证明自己拥有其他化名对自己做出的声明，而不揭示这些化名之间的链接。

<a name="is-a-personcredential"></a>_是人凭证（Is-a-person credential）_：在 Chaum 式凭证中，真名凭证，用于证明其他不可链接化名之间的链接，并防止化名在代理之间转让。

<a name="key"></a>_密钥（Key）_：模糊性和控制的焦点；从如此庞大的名称空间中抽取的随机数，使得幸运猜测的概率极低。非对称密钥对中的公钥半部也可以充当化名。

<a name="biometric"></a>_生物特征（Biometric）_：用于识别特定身体的信息模式，例如指纹、签名笔迹、视网膜扫描、密码等。

<a name="authentication"></a>_认证（Authentication）_：证明正在与拥有特定密钥的代理通信。

<a name="secretkeycryptography"></a>_密钥（对称）密码学（Secret key (symmetric) cryptography）_：使用代理之间共享的密钥进行保密和认证的通信。

<a name="publickeycryptography"></a>_公钥（非对称）密码学（Public key (asymmetric) cryptography）_：使用两个密钥，即私钥和公钥。公钥用于加密对象和验证数字签名。私钥用于解密和签名对象，通常由一个或多个密钥持有人保密。允许在不暴露密钥的情况下分发密钥。

<a name="secretsharing"></a>_秘密共享（Secret sharing）_：将密钥（因此也包括用该密钥加密的任何对象）分成 N 份的方法，其中只需 M 份即可重建密钥，但少于 M 份不提供任何关于密钥的信息。在代理之间分配对象控制权的强大工具。

<a name="digitalsignature"></a>_数字签名（Digital signature）_：基于公钥密码学的密码学协议，证明一个对象曾与对应于该签名的私钥主动接触：该对象被该密钥主动"签署"。也许应该被称为"数字印章"或"数字印记"，因为其功能更像这些方法而非亲笔签名。

<a name="bitcommitment"></a>_比特承诺（Bit commitment）_：数字签名的一种变体，用于承诺一个对象（如承诺或预测）而不在之后揭示该对象。不可能在未被观察的情况下违反协议，或在对象已被承诺后修改它。

<a name="blindsignature"></a>_盲签名（Blind signature）_：数字签名和密钥加密协议的组合，具有可交换性的数学属性，因此可以按照与应用相反的顺序剥离。效果是 Bob"签署"了一个对象，他可以验证其一般形式，但无法看到其具体内容。通常，签名的密钥而非被签署对象的内容定义了被签署对象的含义，因此 Bob 不会最终签署空白支票。用于数字不记名工具（Bob 是清算代理）和 Chaum 式凭证（Bob 是凭证发行方）。

<a name="digitalbearerinstruments"></a>_数字不记名工具（Digital bearer instruments）_：由唯一密钥标识的对象，由清算代理发行、清算和赎回。当对象被转让时，受让人可以请求清算代理验证该密钥之前从未被清算过，并发行新密钥。清算代理防止特定对象的多次清算，但可以被防止将特定对象与转让该对象的一个或两个清算化名链接。这些工具有"在线"变体——在每次转让时清算，因此既可验证又可观察——和"离线"变体——可以在不清算的情况下转让，但只在最终清算时可验证，通过揭示任何转让了该对象多次的中间持有者的清算化名来验证（这是一种违约行为）。对清算代理的隐私可以采取受让人不可链接性、转让人不可链接性或"双重盲化"——转让人和受让人对清算代理都不可链接。数字现金是数字不记名工具的一种流行形式。

<a name="locality"></a>_局部性（Locality）_：_ 即时性，例如数字不记名工具的在线清算所提供的 _ 与最了解的代理打交道 \* 在自己的专业领域内交易

<a name="hotbackup"></a>_热备份（Hot Backup）_：在当前服务发生故障时上线的备份服务。通常由死人开关触发。

<a name="zkip"></a>_零知识交互证明（Zero-Knowledge Interactive Proof, ZKIP）_：一种密码学协议，可用于证明一个代理拥有密钥（并通过较弱的推断表明，其他正常运作且本应有动机正确回应挑战但未能做到的代理不拥有该密钥），而不揭示关于该密钥的任何信息。目前用于认证，以及智能武器中的敌我识别（IFF）。

<a name="smartproperty"></a>_智能财产（Smart Property）_：将所有权所需特征嵌入其中的软件或物理设备；例如，对于缺乏密钥占有权的代理，可以使其价值大幅降低的设备，通过零知识交互证明来演示。实现智能财产的方法可能包括 OND（见下文），以及内置的 immobilizing 或破坏性装置以挫败试图短接财产的行为。

<a name="ond"></a>_运行必需数据（Operation Necessary Data, OND）_：智能财产运行所必需的数据。例如，运行计算机化引擎所需的复杂专有点火序列，制造专用零件所需的 CAD 文件等。为避免服务被窃取，需要 ZKIP 来打开到设备的加密通道。为避免 OND 泄露给 Eve，可以在通道的设备端结合篡改检测和死人开关。

<a name="smartlien"></a>_智能留置权（Smart Lien）_：在当事方之间共享智能财产的控制权，通常是称为所有者和留置权持有者的两方。该财产可能在所有者或留置权持有者的实际占有中，分别对应普通法中的"工匠留置权"和"旅馆留置权"概念。可用于担保信贷额度、保险合同以及许多其他涉及智能财产的合约。

<a name="security"></a>_证券（Security）_：代表一种基础资产，例如所有权份额（股票）或债权（债券、现金）。

<a name="contingentcontract"></a>_或有合约（Contingent contract）_：包含取决于当事方选择或世界状态的条款的合约。期权是或有合约的一个例子。

<a name="derivative"></a>_衍生品（Derivative）_：看涨或看跌期权、期货或合成资产；这种合约是从基础证券"衍生"出来的。

<a name="syntheticasset"></a>_合成资产（Synthetic asset）_：通过组合证券和其他衍生品构建或"合成"的衍生品。复杂合成品的现金流可以通过细粒度决策树高精度计算。

<a name="cashflow"></a>_现金流（Cash flow）_：根据合约条款的预期支付序列。从现金流可以计算合约的基本财务目标，如净现值。
