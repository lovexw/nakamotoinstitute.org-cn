> 《GNU 宣言》（即下文内容）由 [Richard Stallman](https://www.stallman.org/) 于 1985 年撰写，旨在呼吁支持 GNU 操作系统的开发。部分文字取自 1983 年的最初公告。到 1987 年，宣言做了小幅更新以反映后续发展；此后，最好保持不变。
>
> 自那时以来，我们了解到一些常见的误解，不同的措辞可以帮助避免。自 1993 年以来添加的脚注有助于澄清这些要点。
>
> 如果你想安装 GNU/Linux 系统，我们建议你使用 [100% 自由软件的 GNU/Linux 发行版](https://www.gnu.org/distros)。关于如何贡献力量，请参见 [gnu.org/help](https://www.gnu.org/help/help.html)。
>
> GNU 项目是自由软件运动的一部分，这是一场为[软件用户争取自由](https://www.gnu.org/philosophy/free-sw.html)的运动。将 GNU 与"开源"一词联系在一起是错误的——该术语由不同意自由软件运动伦理价值观的人于 1998 年创造。他们用它来推广对同一领域的[非道德方法](https://www.gnu.org/philosophy/open-source-misses-the-point.html)。

## 什么是 GNU？GNU 不是 Unix！

GNU 是 "Gnu's Not Unix" 的缩写，是一个完整的 Unix 兼容软件系统的名称，我正在编写这个系统，以便能免费提供给所有能使用它的人。[^1] 一些其他志愿者也在帮助我。我们非常需要时间、资金、程序和设备方面的贡献。

到目前为止，我们已经有了带有用于编写编辑器命令的 Lisp 的 Emacs 文本编辑器、一个源代码级调试器、一个与 yacc 兼容的解析器生成器、一个链接器，以及大约 35 个实用程序。一个 shell（命令解释器）已接近完成。一个新的可移植优化 C 编译器已经完成了自编译，可能今年就会发布。一个初始内核已经存在，但模拟 Unix 还需要更多的功能。当内核和编译器完成后，就可以发布一个适合程序开发的 GNU 系统。我们将使用 TeX 作为文本格式化工具，但也正在开发一个 nroff。我们还将使用自由的、可移植的 X 窗口系统。之后，我们将添加可移植的 Common Lisp、一个 Empire 游戏、一个电子表格以及数百种其他东西，还有在线文档。我们希望最终能提供通常随 Unix 系统附带的所有有用工具，甚至更多。

GNU 将能够运行 Unix 程序，但不会与 Unix 完全相同。我们将根据在其他操作系统上的经验，对所有方便的方面进行改进。特别是，我们计划拥有更长的文件名、文件版本号、一个不会崩溃的文件系统、文件名自动补全、终端无关的显示支持，也许最终还有一个基于 Lisp 的窗口系统，通过它多个 Lisp 程序和普通 Unix 程序可以共享一个屏幕。C 和 Lisp 都将作为系统编程语言可用。我们将尝试支持 UUCP、MIT Chaosnet 和 Internet 协议进行通信。

GNU 最初面向的是 68000/16000 等级、带有虚拟内存的机器，因为它们是最容易运行 GNU 的机器。让 GNU 在更小的机器上运行所需的额外工作将留给想要在这些机器上使用它的人。

为了避免可怕的混淆，当提到这个项目的名称时，请务必发出 "GNU" 中 _g_ 的音。

## 为什么我必须编写 GNU

我认为黄金法则要求我：如果我喜欢一个程序，我就必须与同样喜欢它的其他人分享。软件销售商想要分化用户并征服他们，让每个用户都同意不与他人分享。我拒绝以这种方式破坏与其他用户的团结。我在良心上无法签署保密协议或软件许可协议。多年来，我在人工智能实验室内部努力抵制这些趋势和其他不善之举，但最终它们走得太远了：我无法留在一个违背我的意愿为我做这些事情的机构中。

为了能够继续体面地使用计算机，我决定组装一套足够的自由软件，这样我就能够在没有不自由软件的情况下继续工作。我已经从人工智能实验室辞职，以否认 MIT 任何阻止我免费分发 GNU 的法律借口。[^2]

## 为什么 GNU 将与 Unix 兼容

Unix 不是我理想的系统，但它还不错。Unix 的基本特性似乎是好的，我认为我可以在不破坏它们的前提下弥补 Unix 的不足。而且一个与 Unix 兼容的系统对许多其他人来说也会很方便采用。

## GNU 将如何提供

GNU 不属于公共领域。每个人都将被允许修改和重新分发 GNU，但不允许任何分发者限制其进一步分发。也就是说，[专有](https://www.gnu.org/philosophy/categories.html#ProprietarySoftware)修改将不被允许。我想确保 GNU 的所有版本都保持自由。

## 为什么许多其他程序员想要帮忙

我发现许多其他程序员对 GNU 感到兴奋并想要帮忙。

许多程序员对系统软件的商业化感到不满。这也许能让他们赚更多的钱，但要求他们在总体上与其他程序员感到冲突，而不是感到同志般的情谊。程序员之间友谊的基本体现是分享程序；而目前通常使用的营销安排基本上禁止程序员把其他人当作朋友对待。软件购买者必须在友谊和遵守法律之间做出选择。自然而然，许多人决定友谊更重要。但那些信仰法律的人往往对两种选择都感到不安。他们变得愤世嫉俗，认为编程只是赚钱的手段。

通过编写和使用 GNU 而非专有程序，我们可以对所有人友善并同时遵守法律。此外，GNU 作为一个榜样来激励他人，也是一面旗帜来号召更多人与我们一起分享。这能给我们带来一种和谐的感觉，如果使用不自由的软件，这种感觉是不可能的。对于与我交谈的大约一半程序员来说，这是一种金钱无法替代的重要幸福感。

## 你如何贡献

> （如今，关于软件任务，请参见[高优先级项目列表](http://fsf.org/campaigns/priority-projects)和 [GNU 求助列表](http://savannah.gnu.org/people/?type_id=1)，即 GNU 软件包的通用任务列表。关于其他帮助方式，请参见[帮助 GNU 操作系统的指南](https://www.gnu.org/help/help.html)。）

我正在向计算机制造商请求捐赠机器和资金。我正在向个人请求捐赠程序和劳动。

如果你捐赠机器，可以预期的一个结果是 GNU 将在早期就能在这些机器上运行。这些机器应该是完整的、即开即用的系统，获得在住宅区使用的许可，且不需要复杂的冷却或电力。

我发现有非常多的程序员渴望为 GNU 贡献兼职工作。对于大多数项目来说，这种兼职的分布式工作非常难以协调；独立编写的部分无法协同工作。但对于替换 Unix 这个特定任务，这个问题不存在。一个完整的 Unix 系统包含数百个实用程序，每一个都有独立的文档。大多数接口规范由 Unix 兼容性所确定。如果每个贡献者能编写一个 Unix 实用程序的兼容替代品，并使其在 Unix 系统上能正常替代原版工作，那么这些实用程序组合在一起就能正常工作。即使考虑到墨菲定律会制造一些意想不到的问题，组装这些组件也是可行的任务。（内核需要更密切的沟通，将由一个紧密的小组来完成。）

如果我获得资金捐赠，我也许能够雇用一些人全职或兼职工作。按程序员的标准，薪水不会很高，但我寻找的是那些认为建设社区精神与赚钱同等重要的人。我把这看作是一种让有奉献精神的人能够全力投入 GNU 工作的方式，而不必再以其他方式谋生。

## 为什么所有计算机用户都将受益

一旦 GNU 写成，每个人都将能够像获得空气一样免费获得好的系统软件。[^3]

这不仅意味着为每个人省下了 Unix 许可证的费用。它还意味着大量浪费的系统编程工作的重复将得以避免。这些精力可以转而用于推进技术前沿。

完整的系统源代码将对每个人开放。因此，需要修改系统的用户将始终可以自己动手，或雇用任何可用的程序员或公司来为他做修改。用户将不再受制于拥有源代码并处于唯一能够进行修改的位置的某个程序员或公司。

学校将能够通过鼓励所有学生研究和改进系统代码来提供一个更具教育性的环境。哈佛大学的计算机实验室曾有这样一个政策：任何程序如果其源代码不公开，就不能安装在系统上，并且他们通过实际拒绝安装某些程序来坚持这一政策。我从中受到很大的启发。

最后，考虑谁拥有系统软件以及一个人被允许或不被允许对其做什么的负担将被消除。

让人们为使用程序而付费的安排，包括副本许可，总是通过繁琐的机制来弄清一个人必须为多少（即哪些程序）付费，从而给社会带来巨大成本。而且只有警察国家才能强迫每个人都遵守。想象一个空间站，那里空气必须以巨大的成本制造：按升向每个呼吸者收费可能是公平的，但整天整夜戴着计量防毒面罩是令人无法忍受的，即使每个人都付得起空气费。而且无处不在的摄像头监控你是否曾摘下面罩，这是令人愤慨的。更好的办法是用人头税来支持空气制造厂，然后丢掉面罩。

复制程序的全部或部分对程序员来说就像呼吸一样自然，也一样富有成效。它应该像呼吸一样自由。

## 对 GNU 目标的一些容易反驳的反对意见

**"如果它是免费的，就没有人会使用它，因为这意味着他们无法依赖任何支持。"**<br />**"你必须对程序收费才能提供支持。"**
: 如果人们宁愿为 GNU 加服务付费，也不愿免费获得没有服务的 GNU，那么一家专门为免费获得 GNU 的人提供服务的公司应该是盈利的。[^4]

    我们必须区分真正的编程工作形式的支持和单纯的手把手教导。前者是不能从软件供应商那里依赖的。如果你的问题没有被足够多的人共享，供应商就会让你滚蛋。

    如果你的业务需要能够依赖支持，唯一的方法是拥有所有必要的源代码和工具。这样你就可以雇用任何可用的人来解决你的问题；你不受制于任何个人。在 Unix 的情况下，源代码的价格使大多数企业无法考虑这一点。有了 GNU，这将变得容易。虽然仍然可能出现没有可用的合格人员的情况，但这个问题不能归咎于分发安排。GNU 不能消除世界上所有的问题，只能消除其中一些。

    同时，对计算机一无所知的用户需要手把手的指导：替他们做一些他们完全可以自己做但不知道怎么做的事情。

    这种服务可以由那些专门销售手把手指导和维修服务的公司来提供。如果用户确实宁愿花钱购买带有服务的产品，他们也会愿意在免费获得产品后单独购买服务。服务公司将在质量和价格上竞争；用户不会被绑定在某一家公司。同时，我们这些不需要服务的人应该能够使用程序而不必为服务付费。

**"不做广告你就无法接触到很多人，你必须对程序收费来支持广告。"**<br />**"为一个人们可以免费获得的程序做广告是没有用的。"**
: 有各种免费或非常廉价的宣传方式可以用来向大量计算机用户告知像 GNU 这样的项目。但通过广告确实可能接触到更多的微型计算机用户。如果确实如此，一家以收费方式广告代为复制和邮寄 GNU 的服务的公司应该能够盈利到足以支付其广告费用甚至更多。这样一来，只有从广告中受益的用户才为其付费。

    另一方面，如果许多人从朋友那里得到 GNU，这样的公司不成功，这将证明广告对于传播 GNU 并不是真正必要的。为什么自由市场的倡导者不想让自由市场来决定这件事呢？[^5]

**"我的公司需要一个专有操作系统来获得竞争优势。"**
: GNU 将把操作系统软件从竞争领域中移除。你将无法在这个领域获得优势，但你的竞争对手也无法对你获得优势。你和他们在其他领域竞争，同时在这个领域互相受益。如果你的业务是销售操作系统，你不会喜欢 GNU，但那对你来说就太糟糕了。如果你的业务是其他事情，GNU 可以使你免于被推入昂贵的操作系统销售业务。

    我希望能看到 GNU 的开发得到许多制造商和用户的赠款支持，从而降低每个人的成本。[^6]

**"难道程序员不应该因其创造力获得奖励吗？"**
: 如果有什么东西值得奖励，那就是对社会的贡献。创造力可以是一种社会贡献，但前提是社会可以自由地使用其成果。如果程序员因为创造了创新的程序而应该获得奖励，那么同理，如果他们限制了这些程序的使用，他们也应该受到惩罚。

**"程序员难道不能为其创造力要求奖励吗？"**
: 想要为工作获得报酬，或寻求最大化自己的收入，这没有什么不对，只要不使用破坏性的手段。但当今软件领域惯用的手段是基于破坏的。

    通过限制用户使用程序来从用户那里榨取金钱是破坏性的，因为这些限制减少了程序可以使用的方式和数量。这减少了人类从程序中获得的财富。当存在故意限制的选择时，其有害后果就是故意的破坏。

    一个好公民不使用这种破坏性手段来变得更富有，原因在于，如果每个人都这样做，我们都会因为相互破坏而变得更穷。这是康德伦理学；或者说，是黄金法则。因为我不喜欢如果每个人都囤积信息所产生的后果，所以我必须认为一个人这样做是错误的。具体而言，想要因自己的创造力获得奖励并不能证明剥夺整个世界对这种创造力的全部或部分使用是正当的。

**"程序员会不会饿死？"**
: 我可以回答说没有人被强迫当程序员。我们大多数人无法靠站在街上做鬼脸来挣到任何钱。但我们并没有因此被注定要花一辈子站在街上做鬼脸并挨饿。我们做别的事情。

    但这是错误的回答，因为它接受了提问者的隐含假设：没有软件所有权，程序员就不可能获得一分钱的报酬。似乎是全有或全无。

    程序员不会挨饿的真正原因是，他们仍然可以通过编程获得报酬；只是不如现在这么多。

    限制复制不是软件业务的唯一基础。它是最常见的基础 [^7]，因为它带来最多的钱。如果它被禁止，或被顾客拒绝，软件业务将转向其他目前较少使用的组织基础。任何一种业务总有多种组织方式。

    在新的基础上，编程可能不会像现在这样有利可图。但这并不是反对变革的论据。售货员目前拿的薪水并不被认为是一种不公正。如果程序员拿同样的薪水，那也不会是不公正。（实际上他们仍然会比售货员挣得多得多。）

**"人们难道没有权利控制自己的创造力如何被使用吗？"**
: "控制自己思想的使用"实际上构成了对其他人生活的控制；而且这通常被用来使他们的生活更加困难。

    仔细研究过知识产权问题的人 [^8]（如律师）说，知识产权没有内在的权利。政府承认的各种所谓的知识产权权利是通过特定的立法行为为特定目的而创造的。

    例如，专利制度的建立是为了鼓励发明者公开其发明的细节。其目的是帮助社会而不是帮助发明者。当时，与现有技术的进步速度相比，17 年的专利期限是相当短的。由于专利只是制造商之间的事情，对他们来说许可协议的成本和努力与建立生产相比微不足道，专利通常不会造成太大的损害。它们不会阻碍大多数使用专利产品的个人。

    古代不存在版权的概念，当时非虚构作品的作者经常大篇幅地抄袭其他作者。这种做法是有用的，也是许多作者的作品得以保存（即使是部分保存）的唯一途径。版权制度的创立专门是为了鼓励创作。在其发明的领域——书籍——只有印刷机才能经济地复制——它几乎没有造成什么损害，也没有阻碍大多数阅读书籍的个人。

    所有知识产权权利都只是社会授予的许可，因为人们认为（无论正确与否）整个社会将因授予这些许可而受益。但在任何具体情况下，我们都必须问：授予这样的许可真的使我们更好吗？我们许可一个人做的是什么样的事情？

    今天程序的情况与一百年前的书籍截然不同。复制程序最简单的方式是从一个邻居到另一个邻居，程序同时拥有截然不同的源代码和目标代码，程序是被使用而非被阅读和欣赏的——这些事实加在一起，创造了一种局面：执行版权的人在物质和精神上都损害了整个社会；在这种情况下，一个人不应该这样做，无论法律是否允许。

**"竞争能让事情做得更好。"**
: 竞争的典范是赛跑：通过奖励获胜者，我们鼓励每个人都跑得更快。当资本主义真正以这种方式运作时，它做得很好；但它的捍卫者错误地假设它总是如此。如果赛跑者忘记了为什么奖励会被提供，变得不惜一切代价想要获胜，他们可能会找到其他策略——例如，攻击其他赛跑者。如果赛跑者打起来了，他们都会很晚到达终点。

    专有和保密的软件在道德上等同于打群架的赛跑者。遗憾的是，我们唯一的裁判似乎并不反对打架；他只是规范打架（"每跑十码，你可以开一枪"）。他真的应该把他们拉开，并因为哪怕只是试图打架而惩罚赛跑者。

**"没有金钱激励，难道不会所有人都停止编程吗？"**
: 实际上，许多人会在完全没有任何金钱激励的情况下编程。编程对某些人——通常是最擅长编程的人——有着不可抗拒的魅力。职业音乐家中也不乏即使没有希望以此谋生也坚持创作的人。

    但实际上这个常见的问题并不适合当前的情况。程序员的报酬不会消失，只是减少。所以正确的问题是，在金钱激励减少的情况下，还会有人编程吗？我的经验表明他们会的。

    十多年来，世界上许多最优秀的程序员在人工智能实验室工作，报酬远低于他们在其他地方可以获得的。他们获得了许多非金钱的回报：比如名誉和认可。而且创造本身也是有趣的，是一种回报。

    然后，当有机会以高薪做同样有趣的工作时，他们中的大多数离开了。

    事实证明，人们会为了金钱以外的理由编程；但如果有机会赚大钱，他们就会开始期望和要求它。低薪组织在与高薪组织的竞争中表现不佳，但如果高薪组织被禁止，它们不一定表现糟糕。

**"我们迫切需要程序员。如果他们要求我们停止帮助邻居，我们必须服从。"**
: 你永远不会紧迫到必须服从这种要求。记住：可以花几百万用于国防，但一分钱也不用于进贡！

**"程序员总得想办法谋生。"**
: 在短期内，这是对的。然而，程序员有许多不通过出售程序使用权来谋生的方法。目前这种做法之所以普遍，是因为它给程序员和商人带来最多的钱，而不是因为这是唯一的谋生方式。只要你想找，就很容易找到其他方法。这里有一些例子。

    一个推出新计算机的制造商将支付把操作系统移植到新硬件上的费用。

    销售 教学、手把手指导和维护服务 也可以雇用程序员。

    有新想法的人可以将程序作为自由软件分发，[^9] 向满意的用户寻求捐赠，或销售手把手指导服务。我见过已经以这种方式成功运作的人。

    有相关需求的用户可以组成用户组，并缴纳会费。一个小组可以与编程公司签约，编写小组成员想要使用的程序。

    各种开发都可以通过软件税来资助：

    假设每个购买计算机的人必须将价格的 x% 作为软件税缴纳。政府将这笔钱交给一个像 NSF 这样的机构来用于软件开发。

    但如果计算机购买者自己向软件开发捐赠，他可以对这笔税进行抵免。他可以捐赠给自己选择的项目——通常是因为他希望在项目完成后使用其成果。他可以对任何金额的捐赠进行抵免，最高不超过他必须缴纳的税款总额。

    总税率可以由纳税人的投票决定，根据他们被征税的金额加权。

    后果：

    - 计算机使用社区支持软件开发。
    - 这个社区决定需要多大程度的支持。
    - 关心自己的份额花在哪些项目上的用户可以自己选择。

    从长远来看，使程序自由是迈向后稀缺世界的一步，在那个世界里没有人需要为了谋生而辛苦工作。人们将可以自由地投入到有趣的活动中——比如编程——只需每周花必要的十小时在立法、家庭咨询、机器人维修和小行星勘探等必要任务上。将不再需要靠编程来谋生。

    我们已经大大减少了整个社会为其实际生产力所必须做的工作量，但这只有很小一部分转化为工人的闲暇时间，因为许多非生产性活动需要伴随生产性活动。这主要是由官僚主义和与竞争的对抗性斗争造成的。自由软件将大大减少软件生产领域的这些内耗。我们必须这样做，以使生产力的技术进步能够转化为我们更少的工作。

[^1]: 这里的措辞过于随意。意图是没有人需要为**许可**使用 GNU 系统而付费。但这些措辞没有说清楚，人们经常将其解读为 GNU 的副本应该总是以极少或不收费的方式分发。这从来不是意图；宣言后面提到了公司提供有偿分发服务的可能性。后来我学会了仔细区分"自由"一词在自由意义上和在价格意义上的不同。自由软件是用户有分发和修改自由的软件。一些用户可以免费获得副本，而另一些用户则付费获得副本——如果这些资金有助于支持改进软件，那就更好了。重要的是，拥有副本的每个人都有与他人合作使用它的自由。

[^8]: 在 1980 年代，我还没有意识到谈论"知识产权"这一"问题"有多大误导性。这个词显然是带有偏见的；更微妙的是，它把各种不同的法律混为一谈，而这些法律涉及的争议截然不同。如今我敦促人们完全摒弃"知识产权"这个词，以免它导致他人以为那些法律构成了一个连贯的议题。清楚的表达方式是分别讨论专利、版权和商标。参见对这个词如何传播混淆和偏见的[进一步解释](https://www.gnu.org/philosophy/not-ipr.html)。
